# AGENTS.md

## What this is

Kumiko Color Mapper — a single-page front-end app that maps images onto equilateral-triangle lattice patterns for paper craft. Built with Vite, no backend.

## Project structure

```
index.html                Vite entry point (root-level, references src/)
src/
  main.js                 App logic (~326 lines, vanilla JS, ES module)
  grid.js                 Equilateral-triangle grid generation (155 lines)
  patterns.js             46 Kumiko pattern definitions + Canvas2D/SVG rendering (436 lines)
  gallery.js              Pattern selector gallery UI (45 lines)
  renderer.js             Preview/zoom/output canvas rendering (78 lines)
  geometry.js             Polygon bounds + average color sampling (60 lines)
  utils.js                rgbToHex helper (16 lines)
  default-image.js        Embedded base64 JPEG sample image (1 line)
  style.css               All styles
tests/
  grid.test.js            Grid geometry unit tests (60 tests, ~769 lines)
  patterns.test.js        Pattern data + rendering unit tests (18 tests, ~204 lines)
package.json              npm project, Vite + vitest dev dependencies
vite.config.js            Build config (outputs to dist/)
verify_kumiko.py          Playwright smoke test
.github/workflows/deploy.yml  CI → Cloudflare Pages
```

## Development

```bash
npm install
npm run dev         # starts Vite dev server on localhost:5173
```

Open `http://localhost:5173` in a browser. Edit files in `src/` — Vite hot-reloads automatically.

## Testing

```bash
npm test            # runs vitest (80 unit tests)
```

Tests cover grid geometry (equilateral triangles, side lengths, vertex alignment, isInverted consistency, tiling completeness, shared-edge adjacency, no duplicates) and pattern data integrity (REAL_PATTERNS structure, buildPatternSvg output, scaling math).

## Grid geometry (crucial — read before modifying)

The grid is an **asanoha lattice** of equilateral triangles with **vertical bases** (not horizontal).

### Key dimensions

| Parameter | UI label | Formula |
|-----------|----------|---------|
| `innerW` | — | `sizeB × pitch × √3/2` |
| `innerH` | — | `sizeA × pitch` |
| `pitchX` | — | `innerW / numCols = pitch × √3/2` |
| `h` | — | `innerH / numRows = pitch` |

Default UI values: sizeA=20 ("Height"), sizeB=42 ("Width"), pitch=50mm.

### Column-based generation

Grid is generated by iterating **columns** (not rows). Each column boundary is at `x = col × pitchX`.

- **Even-parity columns** have vertices at `y = row × h`
- **Odd-parity columns** have vertices at `y = row × h − h/2`

`flipFirst = numCols % 2 === 0` — when numCols is even, column 0 becomes odd-parity (shifted by −h/2). This ensures the first column's triangles extend below y=0 so the clipping boundary cuts complete triangles.

### Triangle types

Each column pair produces two triangle types:

- **Right-pointing** (base on LEFT, apex on RIGHT): two vertices share the left x, third vertex is to the right
- **Left-pointing** (base on RIGHT, apex on LEFT): two vertices share the right x, third vertex is to the left

All triangles are equilateral with side length = `pitch`.

### isInverted flag (pattern orientation)

`isInverted` controls whether the pattern is rotated 180° inside the triangle:

- **Right-pointing → `isInverted: true`** (pattern apex points left, toward the shared edge)
- **Left-pointing → `isInverted: false`** (pattern apex points right, toward the shared edge)

**This is consistent across ALL columns** — both even-parity and odd-parity columns use the same rule. Adjacent triangles sharing an edge always have opposite `isInverted`.

⚠️ **Historical bug**: Previously, even and odd columns had swapped `isInverted` assignments for the same triangle shape, causing the second column's patterns to appear 180° rotated. The fix (`8f3e60c`) made the even-column branch match the odd-column branch.

### Pattern rendering (Canvas2D)

`drawMotif()` in `patterns.js` renders a pattern into a tile using Canvas2D transforms:

1. (If inverted) rotate 180° around tile center
2. Translate to tile center
3. Rotate −90° (maps horizontal-base pattern to vertical-base tile)
4. **Scale uniformly** by `h / pat.w`
5. Translate to center the pattern at origin

⚠️ **Historical bug**: Step 4 and 5 were swapped (`0c77e6c`), causing the pattern to render far outside the tile. Canvas2D transforms are right-multiplied — the translate offset must be in the already-scaled coordinate system.

⚠️ **Historical bug**: Non-uniform scaling `scale(w/pat.h, h/pat.w)` was used instead of uniform `scale = h/pat.w` (`d53b1f6`). The pattern's equilateral triangle outline (w/h ≈ 2/√3 ≈ 1.152) nearly matches the grid's aspect ratio (2/√3 ≈ 1.155), so uniform scaling produces a near-exact match.

### Gallery thumbnails

`buildPatternSvg()` renders SVG thumbnails in the gallery. Patterns are shown in their **native orientation** (horizontal base, apex at top) — no rotation applied. This matches the Wattenberger reference.

## Key conventions

- All JS is vanilla (no frameworks, ES module imports only). No global scope leakage from modules.
- The 46 Kumiko patterns are defined as SVG-path data in the `REAL_PATTERNS` array in `src/patterns.js`. All share dimensions `w ≈ 288, h ≈ 250` (aspect ratio ≈ 2/√3 for equilateral triangles).
- An embedded base64 JPEG (`DEFAULT_IMAGE_B64` in `src/default-image.js`) provides a default sample image on load.
- Color clustering uses a custom deterministic K-means implementation in `src/main.js` (no external lib).
- Pattern paths start with `M` (absolute) or `m` (relative) — both are valid SVG.
- Tests use vitest. `Path2D` (browser API) is mocked globally in pattern tests for Node.js compatibility.
